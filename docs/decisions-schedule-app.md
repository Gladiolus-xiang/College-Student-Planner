# 决策记录 · 大学日程规划（AIGC 大赛）

> 用途：记结论和理由，防止做到一半忘了为什么这么定。文档附录、PPT「设计过程」可直接引用。
> 状态：讨论中，每轮追加。

## 已确定

### D1 · 参赛赛题
- **结论**：赛题一「AI 辅助开发 · 创意产品原型」，网页形态。
- **理由**：交付物是网页原型，一周内可控；赛题一评分侧重「能否用 AI 编码完成界面与交互」，与团队能力匹配。

### D2 · 产品定位：从「记录工具」改为「排期决策助手」
- **结论**：不做「帮你记住 + 提醒你」的待办清单，做「替你决定今天做什么、没做完帮你重排」的 AI 排期工具。
- **理由**：原三条功能（起始日期、总览排序、到点提醒）去掉 AI 后毫发无损，创新性和「AIGC 应用特色」两项会失分。评委必问「把 AI 拿掉还剩什么」。

### D3 · AI 核心环节
- **结论**：以 **B 自动排期** 为主轴，**A 自然语言录入** 为入口，**C 长期目标拆解** 保留轻量版。
- **理由**：B 是唯一「没有 AI 做不出来」的环节，且串起完整闭环：一句话录入 → AI 排期 → 到点提醒 → 打卡 → 未完成自动重排。
- **C 的取舍**：只做「目标 → 一键拆成周期任务 + 打卡」，不做「按完成率动态调难度」（一周内做不完，且演示价值低）。
- **砍掉 D（AI 复盘/鸡汤）**：易被答辩追问成「AI 陪伴」空壳。

### D4 · 目标用户
- **结论**：本班/本年级大学生（b）。支持课表导入，数据以真实课表 + 模拟 DDL 为主。
- **理由**：a 撑不起「应用价值」，c 适配与数据工作量拖垮一周工期；「通用」等于「没有特色」。

### D5 · 时间约束
- **结论**：距教学班推荐截止约 1 周。一切范围以「能演透一个闭环」为唯一标准。
- **理由**：预赛 = 文档 25% + PPT 37.5% + 视频 25% + 诚信 12.5%。原型只要够演，PPT 和文档才是分数主体。

### D6 · 课表导入降级
- **结论**：预置一份示例课表 + 手动添加为主；截图识别（OCR/多模态）作为「可选演示」，只在准备好的截图上跑。
- **理由**：一周内做通用课表解析是最高风险项，失败会直接毁掉演示。

### D7 · 技术栈
- **结论**：Vite 8 + React 19 + TypeScript + Tailwind v4；Node 中间件做模型代理；数据走 localStorage。
- **理由**：无论选哪种方案，key 都必须放服务端（浏览器直连会暴露密钥，且 DeepSeek 跨域不可靠）。既然"零构建"也躲不掉一个服务，它省环境成本的优点就没了；而 React 组件化让 3 人可并行改 UI，AI 生成质量也最高。
- **已验**：`npm.cmd run build` 通过；`/api/chat` 缺 key 时返回中文提示。

### D8 · 密钥策略
- **结论**：key 只读 `app/.env`，变量名不加 `VITE_` 前缀，只由 `server/deepseek.ts` 在服务端使用。
- **理由**：`VITE_` 前缀的变量会被打进浏览器产物；不加前缀则 Vite 不会暴露。这是文档"数据安全"一节的实证。

### D9 · 时间线
- **结论**：截止 2026-11-28。目标 **11-27 晚全部就绪、11-28 上午提交**。
- **理由**：硬截止不给缓冲等于没有截止；提前一天交，11-28 整天当风险储备。

### D10 · 人力
- **结论**：3–4 人，其中队里另有 1 人专做文档 + PPT（角色 C），不参与写代码；无人会前端框架。
- **结论**：代码由 AI 生成，人负责描述需求、验收、记录 Prompt；不要求任何人通读 React 语法。
- **风险**：答辩被问"这段怎么实现的"时答不出 → 每个功能上线时，A/B 各写三句话说明"输入—处理—输出"，存进文档。

### D11 · 时间由代码算，理由由模型写
- **结论**：排期的时段计算、冲突检查、单日上限全部在 `src/lib/schedule.ts` 里用规则完成；模型只负责（a）解释每块安排、写「今日一句」，（b）重排时给先后顺序。
- **理由**：模型不擅长算术和约束检查，让它直接输出时间会出现「凌晨 3 点写作业」「排在课上」「两个任务撞车」。分工后模型出错也不会生成非法计划，等于给演示上了保险。
- **代价**：规则排期不如模型灵活（不会考虑"这门课难，多留时间"），这一条写进「局限与后续」。

### D12 · 提醒的边界
- **结论**：页面开着时，用浏览器通知 + 页面内 Toast 双通道；关掉页面就不提醒。只补发最近 30 分钟内的提醒，不补发几天前的。
- **理由**：网页端做不到「关页面还在后台跑」，硬做要上 Service Worker + 推送服务器，一周内是纯风险。把边界讲清楚反而显得懂技术，写进「当前局限」即可。
- **演示**：页面上放一个「60 秒后演示提醒」按钮，录屏时点一下，继续讲解，60 秒后通知弹出——这个空档正好用来讲技术路径。
