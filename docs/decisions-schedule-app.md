# 决策记录 · 大学日程规划（AIGC 大赛）

> 用途：记结论和理由，防止做到一半忘了为什么这么定。文档附录、PPT「设计过程」可直接引用。
> 状态：讨论中，每轮追加。

## 已确定

### D1 · 参赛赛题
- **结论**：赛题一「AI 辅助开发 · 创意产品原型」，网页形态。
- **理由**：交付物是网页原型，一周内可控；赛题一评分侧重「能否用 AI 编码完成界面与交互」，与团队能力匹配。

### D2 · 产品定位：从「记录工具」改为「排期决策助手」
- **结论**：不做「帮你记住 + 提醒你」的待办清单，做「替你决定今天做什么、没做完帮你重排」的 AI 排期工具。
- **理由**：原三条功能（起始日期、总览排序、到点提醒）去掉 AI 后毫发无损，创新性和「AIGC 应用特色」两项会失分。评委必问「把 AI 拿掉还剩什么」。

### D3 · AI 核心环节
- **结论**：以 **B 自动排期** 为主轴，**A 自然语言录入** 为入口，**C 长期目标拆解** 保留轻量版。
- **理由**：B 是唯一「没有 AI 做不出来」的环节，且串起完整闭环：一句话录入 → AI 排期 → 到点提醒 → 打卡 → 未完成自动重排。
- **C 的取舍**：只做「目标 → 一键拆成周期任务 + 打卡」，不做「按完成率动态调难度」（一周内做不完，且演示价值低）。
- **砍掉 D（AI 复盘/鸡汤）**：易被答辩追问成「AI 陪伴」空壳。

### D4 · 目标用户
- **结论**：本班/本年级大学生（b）。支持课表导入，数据以真实课表 + 模拟 DDL 为主。
- **理由**：a 撑不起「应用价值」，c 适配与数据工作量拖垮一周工期；「通用」等于「没有特色」。

### D5 · 时间约束
- **结论**：距教学班推荐截止约 1 周。一切范围以「能演透一个闭环」为唯一标准。
- **理由**：预赛 = 文档 25% + PPT 37.5% + 视频 25% + 诚信 12.5%。原型只要够演，PPT 和文档才是分数主体。

### D6 · 课表导入降级
- **结论**：预置一份示例课表 + 手动添加为主；截图识别（OCR/多模态）作为「可选演示」，只在准备好的截图上跑。
- **理由**：一周内做通用课表解析是最高风险项，失败会直接毁掉演示。

### D7 · 技术栈
- **结论**：Vite 8 + React 19 + TypeScript + Tailwind v4；Node 中间件做模型代理；数据走 localStorage。
- **理由**：无论选哪种方案，key 都必须放服务端（浏览器直连会暴露密钥，且 DeepSeek 跨域不可靠）。既然"零构建"也躲不掉一个服务，它省环境成本的优点就没了；而 React 组件化让 3 人可并行改 UI，AI 生成质量也最高。
- **已验**：`npm.cmd run build` 通过；`/api/chat` 缺 key 时返回中文提示。

### D8 · 密钥策略
- **结论**：key 只读 `app/.env`，变量名不加 `VITE_` 前缀，只由 `server/deepseek.ts` 在服务端使用。
- **理由**：`VITE_` 前缀的变量会被打进浏览器产物；不加前缀则 Vite 不会暴露。这是文档"数据安全"一节的实证。

### D9 · 时间线
- **结论**：截止 2026-11-28。目标 **11-27 晚全部就绪、11-28 上午提交**。
- **理由**：硬截止不给缓冲等于没有截止；提前一天交，11-28 整天当风险储备。

### D10 · 人力
- **结论**：3–4 人，其中队里另有 1 人专做文档 + PPT（角色 C），不参与写代码；无人会前端框架。
- **结论**：代码由 AI 生成，人负责描述需求、验收、记录 Prompt；不要求任何人通读 React 语法。
- **风险**：答辩被问"这段怎么实现的"时答不出 → 每个功能上线时，A/B 各写三句话说明"输入—处理—输出"，存进文档。

### D11 · 时间由代码算，理由由模型写
- **结论**：排期的时段计算、冲突检查、单日上限全部在 `src/lib/schedule.ts` 里用规则完成；模型只负责（a）解释每块安排、写「今日一句」，（b）重排时给先后顺序。
- **理由**：模型不擅长算术和约束检查，让它直接输出时间会出现「凌晨 3 点写作业」「排在课上」「两个任务撞车」。分工后模型出错也不会生成非法计划，等于给演示上了保险。
- **代价**：规则排期不如模型灵活（不会考虑"这门课难，多留时间"），这一条写进「局限与后续」。

### D12 · 提醒的边界
- **结论**：页面开着时，用浏览器通知 + 页面内 Toast 双通道；关掉页面就不提醒。只补发最近 30 分钟内的提醒，不补发几天前的。
- **理由**：网页端做不到「关页面还在后台跑」，硬做要上 Service Worker + 推送服务器，一周内是纯风险。把边界讲清楚反而显得懂技术，写进「当前局限」即可。
- **演示**：页面上放一个「60 秒后演示提醒」按钮，录屏时点一下，继续讲解，60 秒后通知弹出——这个空档正好用来讲技术路径。

### D13 · 固定日程的三条硬规则（2026-11-22 修正）
- **结论**：
  1. 只有日期、没有具体时刻的活动（deadline 落在 23:59）不允许是固定日程，提示词与引擎双重拦截。
  2. 排期只排除「没有截止时间的 course」（那是周课表条目），有截止时间的一次性活动（社团培训、讲座）必须参与排期。
  3. 当天的可用时间从「现在」开始，不能把任务排到已经过去的时段。
- **理由**：演示时这三类错误都会立刻被看见——时间倒挂（23:59–23:00）、活动凭空消失、以及把任务排到早上八点而当时已是下午。
- **代价**：没有。三条都是纯约束收紧。

### D14 · 截图识别（课表 / 群通知）
- **结论**：用 DeepSeek 的视觉模型 `deepseek-flash`（与 chat 同一个 API、同一个 key），前端把图片压到最长边 1600px 后以 base64 内联，走同一个 `/api/chat` 代理。
- **理由**：模型端本来就会把图片缩到约 1300×1300，提前压缩只减少上传体积；图片按张计费且有 1024 token 上限，成本可以忽略。视觉模型直接读版式，比 OCR 再让文本模型猜结构更可靠。
- **入口**：群通知截图既可能从按钮选，也可能直接 Ctrl+V 粘贴或拖进输入框（演示时这一步最抓人）。
- **边界**：PPT/文档里的「不承诺」要同步改掉——课表识别现在有了，但只对清晰截图可靠；手写、歪拍、复杂合并单元格仍然会错。

### D15 · 文档以 docx 为唯一真源
- **结论**：`deliverables/项目文档-初稿.docx` 是唯一真源。后续改动一律**在文件内定点修改**（按文本定位段落、复制表格行再替换文字），不再运行 `build_doc.py` 整体重建。
- **理由**：团队在 Word 里手改过内容，整体重建会全部覆盖。`build_doc.py` 只在“从零重来”时才用，平时跑一次就是事故。
- **代价**：每次改动要写一个小脚本（`scripts/sync_*.py`），但这些脚本只按文本定位，不会碰别的段落。
- **配图替换**：图片按「文档内出现顺序」定位，不按部件 id——否则会把闭环图和架构图对调（已踩过一次）。

### D16 · 计划窗口按截止动态扩展
- **结论**：窗口 = max(3 天, 覆盖最远截止所需天数)，上限 7 天；排不进窗口的活动在计划下方显式列出。
- **理由**：固定 3 天时，「下周三」的活动会落在窗口外，用户以为它丢了——这比排错更伤信任。上限 7 天是为了避免有人填了 12 月的考试，页面一次性铺开二十天。
- **代价**：窗口最长时一屏放不下，需要滚动；可接受。

### D17 · 允许别人访问：EdgeOne Makers 静态托管 + 边缘函数
- **结论**：页面部署到腾讯 EdgeOne Makers 免费版；`/api/chat` 由 `app/edge-functions/api/chat.js` 的边缘函数执行；密钥放平台环境变量；每日额度用 KV 记两个计数器（全局 + 单 IP）。
- **理由**：约束是「国内几十人能打开、0 元、没有服务器和域名」。Cloudflare Workers 的 `workers.dev` 在国内被墙、Vercel 没有大陆节点（官方 KB 明说），本机隧道又依赖电脑不关机——只有「国内平台二级域名 + 免费函数」同时满足。二级域名不需要备案，备案要 1–2 周，赶不上 11-28。
- **取舍**：边缘函数请求体上限 1 MB，所以前端把截图压到 1280px / JPEG 0.82，超了自动再降一档，仍超就报「裁剪后再试」；KV 是最终一致（跨节点最多 60 秒），并发下额度会少量超发——它是「防链接被转发」的刹车，不是计费依据。
- **安全**：代理只接受同源请求（线上缺 `Origin` 一律 403，本地开发放行，因为回归脚本用 Node fetch 直连）；key 仍然只存在于服务端。
- **代价**：免费版无 SLA；环境变量、KV 绑定都在控制台，改完要重新部署。部署步骤见 `docs/deploy-edgeone.md`。

### D18 · 去重：同一件事只留一份
- **结论**：录入时按「标题（去掉空白、书名号、括号，忽略大小写）+ 截止时间」判重。同一张截图连贴两次、模型一批里把一件事说了两遍、历史数据里的重复，都在入口处消掉。
- **理由**：重复条目会让排期把同一段时间切成两半（两小时的任务显示成两块各一小时），用户会以为系统算错；演示时「再贴一次」是最容易发生的动作。
- **取舍**：同名同截止但确实是两件事（两份同标题同截止的实验报告）会被合并。换成「弹窗让用户确认」会多一次打断，对演示是负收益。
- **实现**：`src/lib/dedupe.ts` 一处口径；截图走「与已有列表比对」，纯文字解析整批替换；课表按「名称 + 星期 + 起止」判重。

### D19 · 区分「开始时间」与「截止时间」
- **结论**：原文写「几点 + 有某事」（今天 15:53 有线代复习、七点半开会、下午两点答疑）时，那个时刻是**开始时间**。解析成 fixed=true，`deadline` 存这个开始时刻；排期把它占成 [开始, 开始+时长]；界面与理由文案一律说「开始」，不写「截止」。
- **理由**：把 15:53 当截止时，卡片显示「截止 15:53 · 1 分钟后」，排期把它当成「要在 15:53 前做完的待办」，排到 16:00–17:00——用户看到的是一份「一打开就已经迟到」的计划。
- **取舍**：数据模型仍只有一个时刻字段（fixed 时语义是「到场」），没有拆成 startAt/endAt。拆字段要同时改提示词、排期、重排、文档四处，收益只是命名更干净；用一处注释 + 一处文案兜住，成本低得多。
- **验证**：`smoke-start-time.mjs` 6 项断言——解析出 fixed=true、保留 15:53、时长 90 分钟、排期占住 15:53–17:23。

### D20 · 截图入口合并为一个，解析改为「追加 + 去重」
- **结论**：页面上只留一个「贴截图识别」按钮，粘贴、拖图也走它。视觉提示词只有一条：先判断图里是课表还是群通知，再输出 `{"kind":"course","courses":[...]}` 或 `{"kind":"notice","activities":[...]}`。文字解析不再整批替换，改成去重后追加；解析结果支持逐条删除与一键清空。
- **理由**：两个按钮做的是同一个动作（选图 → 识别），用户分不清该点哪个，视觉上也是重复的。更要紧的是「再解析一次」原本会清空全部活动——导入课表后随手改个文字再解析，课表相关的活动就没了，把「补充信息」做成了「覆盖数据」。
- **取舍**：同一件事改了截止时间后再解析，会留下新旧两条（判重键含截止时间）。用逐条删除兜住；不改成「同名覆盖」，因为两份同标题的实验报告是真实存在的。
- **验证**：`smoke-vision.mjs` 两条断言（课表图 → kind=course 10 条、群聊图 → kind=notice 3 条）；去重逻辑由 `smoke-dedupe.mjs` 覆盖。
