## 一、技术方案对比

### 方案 A：无构建单页（原生 JS + Tailwind CDN）
- **技术栈**：单个 `index.html` + 原生 JS + Tailwind CDN + localStorage
- **为什么适合**：双击就能开，没有 Node 环境门槛
- **开发难度 / 维护成本**：起步极低，但代码过 800 行后极难改；AI 每改一个交互要重生成大段
- **目标地区能否顺利使用**：可以
- **你得自己管的东西**：密钥（见下，仍然绕不开服务端）、浏览器缓存清理
- **主要风险**：需求反复时崩盘；单文件 diff 冲突，多人没法并行

### 方案 B：Vite + React + TS + Tailwind + 极简代理
- **技术栈**：Vite + React + TypeScript + Tailwind；数据存 localStorage；一个 Node 中间件转发 DeepSeek 请求
- **为什么适合**：AI 编码工具对 React 生态生成质量最高、最会改；组件化让 3 人能并行；构建产物是纯静态，能丢 Vercel 拿"原型链接"加分
- **开发难度 / 维护成本**：需一人会 `npm install` / `npm run dev`，约半小时上手；之后每次改动是改单个组件
- **目标地区能否顺利使用**：可以（DeepSeek 国内直连）
- **你得自己管的东西**：`.env` 里的 API key、代理路由、依赖版本
- **主要风险**：Node 环境装不上（用国内镜像解决）；跨域/代理配错（Day 1 先验）

### 方案 C：Next.js 全栈
- **技术栈**：Next.js App Router + API Route + localStorage/后端存储
- **为什么适合**：key 天然在服务端，一栈到底
- **开发难度 / 维护成本**：一周内属过度设计，构建慢、报错栈深、AI 生成后排查成本高
- **目标地区能否顺利使用**：可以
- **你得自己管的东西**：同上，外加服务端部署
- **主要风险**：7 天里花两天在和框架打架

### 推荐：方案 B

**决定性理由：无论选哪个方案，key 都必须放在服务端代理（浏览器直连会暴露密钥，且 DeepSeek 的跨域不可靠）。既然 A 也躲不掉一个 Node 服务，它"零环境"的优势就不存在了，而 React 在"一周内反复改 UI"这件事上的收益是压倒性的。**

C 的唯一优势（key 在服务端）用 30 行代理就解决了，剩下的只有复杂度。

## 三、数据结构（先定，后写代码）

```ts
type ActivityType = 'course' | 'ddl' | 'habit' | 'goal';

interface Activity {
  id: string;
  title: string;
  type: ActivityType;
  deadline?: string;        // ISO，ddl/goal 用
  durationMin?: number;     // 预计耗时
  priority: 1 | 2 | 3;      // AI 给，用户可改
  remindBeforeMin?: number;
  source: 'ai' | 'manual';
  status: 'todo' | 'done' | 'skipped';
  checkins?: string[];      // habit：打卡日期
}

interface CourseSlot { id: string; name: string; weekday: 1-7; start: string; end: string; }

interface PlanBlock { date: string; activityId: string; start: string; end: string; reason: string; }
```

存储：`localStorage` 三个 key（`activities` / `courses` / `plan`），加一个 `schemaVersion` 便于改结构。

## 四、AI 调用设计（文档与 PPT 的核心素材）

| 调用 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| P1 抽取 | 用户粘贴的原始文本 | `Activity[]` JSON | 不编造字段，缺失留空；类型只能取 4 个枚举值 |
| P2 排期 | 课表空档 + 未完成任务 + 当前时间 | `PlanBlock[]` + 理由 | 先保 deadline；单日任务总时长 ≤ 4h；晚间不排课 |
| P3 重排 | 未完成项 + 原计划 | 新 `PlanBlock[]` + 调整说明 | 保住硬 deadline；说明"为什么挪到这天" |

工程要求（写进文档能加分）：
- 全部用 JSON 输出模式，拿 `response_format: { type: 'json_object' }`
- 前端做 schema 校验，不合法自动重试 1 次，再失败降级到"手动填写"
- 记录每次调用的 prompt、耗时、token、是否重试 → 直接变成文档附录

## 六点五、工程现状（11-21 晚）

已在 `D:\AIGC\app` 落地并验证：

- Vite 8 + React 19 + TypeScript + Tailwind v4，`npm.cmd run build` 通过
- `server/deepseek.ts`：`POST /api/chat` 代理，key 只读 `.env`（每次请求重读，改完不用重启），不进浏览器产物；每次调用写 `logs/ai-calls.jsonl`
- **P1 录入**：粘贴文字 → 活动卡片（含固定日程判定、时间归一化、「还剩 N 天」）
- **P2 排期**：`src/lib/schedule.ts` 规则引擎（避开课程与饭点、单日上限 4 小时、习惯每天一次、固定日程只占时间不排准备）
- **P3 解释**：模型给每块计划写一句理由 + 「今日一句」，失败自动退回规则文案
- **打卡**：习惯类每日打卡、连续天数（今天没打从昨天起算，断一天归零）
- **提醒**：每 15 秒扫描，浏览器通知 + 页面内 Toast；只补发 30 分钟内；「60 秒后演示提醒」按钮用于录屏
- **重排**：勾掉已完成 → 点「今天没做完，重排」→ 模型只给先后顺序，引擎从明天起重算时间
- **持久化**：数据存 localStorage，刷新不丢
- 回归脚本：`scripts/smoke-parse.mjs` / `smoke-plan.mjs` / `smoke-reasons.mjs` / `smoke-reminder.mjs` / `smoke-reorder.mjs`

**实测**：解析 1292ms/245 tokens；理由 1523ms/348 tokens；重排 1385ms/422 tokens。

**P0 六件事已全部跑通**，进入「冻结功能、打磨交付物」阶段。
